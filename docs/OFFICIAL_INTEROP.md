|---|---|---|

| 官方 -> BlockTalk | 接收 310 包；成功解码 308 帧；PLC 0 帧；混音后向实际输出写入 308 个语音帧；本地发送仍为 0 | 用户反馈“能听到”，确认本方向听音 |
| 第一次 BlockTalk -> 官方 | `talk 5`；5 秒内实际发送 249 帧；自动关闭发送门 | 用户先反馈清楚听到，随后纠正为“有严重杂音”；以纠正后的反馈记录本次质量失败 |
| 恢复发送门重试 | 第二次 `talk 5`；实际发送 249 帧；自动关闭 | 用户反馈“现在正常了”，确认该次声音正常 |
| 停止后复核 | 累计发送 498 帧，后续状态查询未再增加；门状态 `press_again` | 发送已停止，随后退出联调会话并释放设备 |

语音帧为 48 kHz、20 ms、Opus Voice。两次发送之间只重新打开 PTT 发送门，
没有变更编解码器实现、音量或增益配置。未保存原始音频，没有人工测量声学噪声、
信噪比、延迟或丢包；表中的 PLC 0 只代表该次本地接收解码路径未执行 PLC。

## 能确认和不能确认的范围

已确认：一个用户安排的官方客户端与独立运行的正式 BlockTalk 核心之间，
两个方向均有真实声音被用户听到；重试的反向声音正常；发送门限时自动关闭。

尚无足够证据区分，不将其归因于用户设备、网络、反馈回路或编解码器中的任一项。
下一步应使用明确设备/耳机、记录双方版本、反复短按及持续讲话来复现，并核对
